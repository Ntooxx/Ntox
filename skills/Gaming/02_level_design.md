# Level Design

## Triggers
- "design a level"
- "level layout"
- "map design"
- "difficulty pacing"
- "greybox help"
- "player flow"
- "teach without tutorials"

## Purpose
Designs playable levels from a stated player experience: establish intent, structure beats, teach mechanics without text, and pace tension so the level reads as a sentence, not a hallway.

## Core Principle

A level is a conversation: you ask a question with space, the player answers with a choice, you reward the answer. If the player can walk it without deciding, it is a corridor with decoration.

## Design Workflow

1. Write the one-line experience: "the player should feel hunted, then clever, then powerful."
2. Pick the verb the level teaches or tests (sneak, aim, balance, route-finding) — one primary verb per level.
3. Block the beats: intro (safe read) -> teach (isolated practice) -> twist (combine with a new variable) -> climax (full expression) -> release (reward + exhale).
4. Use sightlines as breadcrumbs: the next objective should be glimpsed before it is reached; light, motion, and framing point the way.
5. Gate with locks and keys the player already understands — new mechanics get their own quiet room first.
6. Place failure kindly: die -> retry under 15 seconds, no repeated dialogue, checkpoint before the hard ask.
7. Greybox and play it before art exists — if it is not fun in greybox, texture will not save it.

## Pacing Checks

- Tension graph over time: never flat for more than a third of the level.
- Optional content sits off the critical path but on a visible shortcut back.
- The hardest moment is not the last moment — leave a exhale beat after the climax.
- Secrets reward curiosity with either advantage or delight, never required progression.

## Common Errors

- Teaching by textbox instead of by safe practice space.
- Symmetry everywhere: perfect symmetry reads as arena, not place.
- Signposting with floating arrows only — trains players to ignore the world.
- One path, no choices, decorated as "linear is fine" — linear still needs micro-decisions (routes, resources, risks).

## Output Format

Deliver: the one-line experience, beat list as a numbered sequence with the mechanic each beat uses, a sightline/key-light plan for the critical path, failure/retry notes, and the greybox metrics (target clear time, death budget, secret count).
