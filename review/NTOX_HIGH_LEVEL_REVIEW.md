## 5. Findings

### P1 — Learned strategy guidance is discarded under the default configuration

*Evidence:* src/core/agent.ts:1742 — `strategyPrompt && !cfg.cognitiveKernel.isEnabled()`

The Thompson-sampling bandit selects a stance and produces guidance, but the prompt section is only emitted when the cognitive kernel is disabled. Cognition defaults to enabled, so the main behavioural payoff of the bandit never reaches the model.

*Fix:* Compose strategy guidance unconditionally, or gate it on the absence of a kernel-produced equivalent. Add a default-config test that asserts the guidance appears.

### P1 — MCP tools bypass the workspace tool policy

*Evidence:* src/mcp/bridge.ts:216 — `this.registry.register(`

Built-in tools are wrapped in enforceToolPolicy before registration. MCP tools are registered directly into the same registry, so a configured external server can expose capabilities the active workspace profile denies.

*Fix:* Route MCP registrations through the same policy wrapper, using the server name as the policy subject.

### P1 — Sandboxing is off by default on Windows and silently degrades to host execution

*Evidence:* src/tools/shell.ts:228 — `config.dockerEnabled || !IS_WINDOWS`

Docker is attempted automatically on POSIX but only when explicitly enabled on Windows. If the Docker probe fails the shell falls through to host execution, so the sandbox is a best-effort wrapper rather than a boundary.

*Fix:* Make sandbox mode explicit and fail closed when it is requested, or surface the degraded state in /trace and to the user.

### P1 — Every documented install path is broken

*Evidence:* README quick start offers npm, curl and PowerShell; all three end in `npm install -g ntox`, and the registry returns 404

install.sh and install.ps1 check for Node, then run `npm install -g ntox@latest`. With no published package, none of the three advertised entry points can succeed, so the product is only reachable by cloning the repository and building it.

*Fix:* Publish to npm, or point the installers at a release tarball that actually resolves.

### P2 — Reflection output is delivered to a callback and never stored

*Evidence:* src/core/agent.ts:2231 — `if (reflection && callbacks.onReflection) {
            callbacks.onReflection(reflection)`

The reflector makes a real LLM call, then hands the text to a UI callback. Nothing writes it to memory, the mistake journal or the next system prompt, and the feature defaults to off.

*Fix:* Persist reflections with a confidence and a decay window, then inject the ones that are still relevant into the next prompt.

### P2 — The symbolic decision kernel only runs behind a slash command

*Evidence:* src/core/agent.ts:1191 — `startsWith("/kernel")`

Goals, subtasks, dependency ordering and the verifier are implemented, but the routing entry point returns null unless the input begins with /kernel. It is a demo surface, not part of the normal agent loop.

*Fix:* Promote goal decomposition to a tool the model can call, and verify subtask success predicates automatically.

### P2 — Core agent file has grown into a monolith

*Evidence:* src/core/agent.ts:360 — `class Agent`; file is 2834 lines

The main loop, prompt assembly, memory wiring, surprise handling, reflection, tool routing and persistence live in one file above 2,000 lines with a 60KB+ test file beside it.

*Fix:* Extract prompt composition, post-turn learning and tool execution into separate modules with explicit interfaces.

### P2 — Theory confidence is raised by domain similarity, not task outcome

*Evidence:* src/research/theory-store.ts:135 — `confidence =`

Recent observations in the same domain are treated as confirmation, so a theory can gain confidence without ever predicting anything that was checked. Only false-success detection lowers it.

*Fix:* Tie theory confidence to resolved predictions with recorded Brier error, and require an explicit prediction per confirmation.

### P2 — 3 registered tools are unreachable under the default workspace policy

*Evidence:* 25 tools registered in dispatcher.ts, 22 names in DEFAULT_ALLOWED_TOOLS (config.ts:135)

The model sees tools it cannot call. Calls fail at policy time rather than being absent from the schema, which produces avoidable retries.

*Fix:* Project the registry through the active policy when building the tool schema.

### P2 — Line coverage is 62.91% with 52.97% branches

*Evidence:* coverage/coverage-summary.json

The untested surface sits in the modules that carry the differentiation claim: cognition, policy and the post-turn learning path.

*Fix:* Set a per-directory coverage floor for src/cognition, src/mind and src/core/policy.ts.

### P2 — Bus factor is one

*Evidence:* 48 commits, 1 author(s), since 2026-07-24

No external maintainers, no co-authored commits, no review trail. That is a risk signal for anyone considering adoption, independent of code quality.

*Fix:* Recruit a second maintainer, or document a governance and handover model.

### P3 — Self-awareness asks for feedback on a hardcoded confidence

The feedback trigger passes a literal 0.5 instead of the stance calibration the system already computes, so the claim of measured self-knowledge is weaker than advertised.

## 7. Method and limits

- **Measured:** file and line counts, tool registration versus allowlist, provider table, blocklist size, test results, typecheck, lint, coverage artifact, git history, npm registry lookup.
- **Probed:** 9 code signatures that detect dead wiring, suppression flags and policy bypasses; each hit is quoted with file and line.
- **Estimated:** competitor scores, product positioning, and the market read. They are directional and confidence-labelled in `scripts/review/competitors.json`.
- **Not covered:** live model quality, latency, real task-completion rates, cost per task, desktop UX (separate audit in `docs/UI_UX_AUDIT.md`), and long-run learning effects. A benchmark for these exists in `src/benchmark` but requires provider credentials.
- **Bias controls:** signals are fixed before scoring; marketing claims are audited against measured values; code is scored from call sites rather than module existence; a dimension cannot be lifted by adding files.
