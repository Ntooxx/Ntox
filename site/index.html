01 the loop

One law runs the
entire system.

Every cognitive feature must predict, observe, attribute and update. A feature that cannot name its prediction and its update is decoration. NTOX enforces that contract on every single turn.

01

predict

State the expected outcome and confidence before acting.

  1. 01

    Predict

    A free heuristic predictor, or an optional model-backed one, states the expected outcome and its confidence before a single tool runs.

  2. 02

    Act

    The turn executes: model, tools, policy, memory and skills, all routed through one composition root.

  3. 03

    Observe

    Corrections, rephrases, thanks, tool failures, test results and objective signals are captured into the outcome ledger.

  4. 04

    Attribute

    Credit is assigned to the specific memories, theories, skills and context items that were actually present.

  5. 05

    Update

    A Thompson-sampling bandit adjusts strategy, a calibration tracker adjusts confidence, a capability model adjusts domain strength.

  6. 06

    Reuse

    Memory is re-ranked by reliability, context is recompiled under a token budget, and the winning strategy is selected again.

03 capability

Depth where it
actually matters.

Not a wrapper around an API call. A runtime with memory, self-models, a symbolic control layer, and the tooling to keep it honest.

memory

Memory with authority

Corrections outrank older conflicting facts. Durable facts carry provenance, confidence, contradiction counts and a full edit history. Retrieval is ranked by measured usefulness, not just similarity or recency.

  • correction precedence
  • provenance
  • reliability ranking
  • user model

theories

Falsifiable by design

Observations become patterns, patterns become theories, theories become meta-theories. Each carries predictions, falsification criteria and evidence-driven confidence.

skills

81 reasoning frameworks

Markdown skills across 17 category folders, matched semantically at prompt time, with a learner that extracts new ones from experience.

strategy

Thompson sampling

A contextual bandit chooses between standard, direct, verify and clarify stances per query type, and learns which one earns the better outcome.

control

Symbolic decision layer

Goals, subtasks with dependencies, explicit success predicates and a verifier that records outcomes independently of the language model.

observability

Everything is inspectable

/trace shows mode, strategy, memory and theory use, token ledger, policy decisions, tool calls and checkpoints. /mind shows identity, divergence, transfer and the learning curve. Autonomy has a budget, and the budget is visible.

  • token ledger
  • pre-edit checkpoints
  • outcome ledger
  • calibration

04 alive

Alive is a control
loop, not a feature.

ntox/alive models the agent as an event-driven system with explicit expectations. It does not call a model on its own and it does not watch your machine. A host supplies consented events; the engine decides cheaply what deserves cognition.

prediction

statement · confidence · expected event

event

consented · typed · sourced

learnprediction resolved
wakesurprise above threshold

ignorenot worth cognition

Open loops

Goals and hypotheses awaiting evidence, with deadlines. The engine blocks the ones that stall and surfaces them.

Prediction error

Confidence is compared against reality. The gap, not the story, decides whether the agent should wake up.

Privacy bounded

Host adapters watch only the active workspace and Git state. Never typing, never other applications, never remote services.

06 trust

Defence in depth,
by default.

NTOX assumes the model can be wrong, the web can be hostile and the shell can be dangerous. Protections are layered, and every tool from every entry point passes through one policy choke point.
