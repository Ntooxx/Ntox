ntox / agent runtime

An agent with a loop, not a longer prompt.

NTOX predicts before it acts, observes what happened, credits the context it used, and updates the next turn. A closed loop, not a longer prompt.

02 instrumented

Measure the loop.
Not just the output.

Most agents tell you what they did. NTOX scores how well it knew what it was doing, and writes that down too.

Predictions are scored

Every turn states an expected outcome and a confidence first. Brier score and expected calibration error are computed against what actually happened, tracked per stance.

Outcomes are logged

Every turn writes one row: context used, tools called, prediction, error, reward. A single readable ledger at ~/.ntox/mind/outcomes.jsonl.

Everything is inspectable

/trace shows stance, tokens, cost, policy decisions and checkpoints. /mind shows calibration, divergence and the learning curve.

03 capability

The parts that
are actually built.

memory

Memory with authority

Corrections outrank older conflicting facts and are injected ahead of them. Durable facts carry provenance, confidence and an edit history. Retrieval is re-ranked by recorded reliability, not only recency.

library

81 written frameworks

A reasoning library matched semantically at prompt time, across 17 categories, with a learner that extracts more from experience.

strategy

Stance selection

A Thompson-sampling bandit picks between standard, direct, verify and clarify per query type, and learns from the outcome record.

control

Symbolic goals

Goals, subtasks with dependencies, explicit success predicates and a verifier that records outcomes independently of the model.

06 trust

Guard rails,
by default.

Every tool call from every entry point goes through one policy runtime.

workspacereads, writes and shell confined to the active profile
recoverypre-edit checkpoints and an approval queue for risky commands
secrets.ssh .aws .env .gnupg denied, output sanitised
networklocalhost, private ranges and file:// rejected
shelldestructive-command blocklist, Docker sandbox where available

Shell commands run without process isolation on Windows unless dockerEnabled is set. The blocklist is a guard rail, not a boundary.
